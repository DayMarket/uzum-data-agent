# Superset Dashboard Error Fixer

## Назначение

Автоматический дебаггер, который:
1. Находит чарты с ошибками на дашбордах Superset
2. Разбирает причину ошибки по логам и тексту ошибки
3. Прослеживает источники данных (датасеты, таблицы, DAG)
4. Предлагает и выполняет фиксы (только с подтверждением человека)

## Когда использовать

Используй этот скилл, когда просят:
- Починить сломанные чарты на дашборде
- Разобраться, почему чарт не грузится
- Проверить дашборды команды на ошибки
- Расследовать падения чартов и предложить фиксы

## Общий процесс

```
1. ЧЕЛОВЕК даёт URL дашборда или просит проверить дашборды команды
2. АГЕНТ находит чарты с ошибками
3. АГЕНТ читает тексты ошибок и логи
4. АГЕНТ прослеживает источники данных
5. АГЕНТ предлагает фиксы с объяснением
6. ЧЕЛОВЕК подтверждает конкретные фиксы
7. АГЕНТ выполняет только подтверждённые фиксы
```

## КРИТИЧНО: нужно подтверждение человека

**НИКОГДА не применяй фиксы без явного подтверждения!**

После того как нашёл проблемы:
1. Покажи полный список сломанных чартов
2. Объясни причину для каждой ошибки
3. Опиши, как каждую можно починить
4. Спроси, какие фиксы применить
5. Выполняй только то, что подтвердил человек

## Источники данных: OpenMetadata

**Для проверки источников данных и lineage используй коннектор `openmetadata` напрямую.**

Он умеет: искать датасеты/таблицы по имени, отдавать полную информацию о сущности
(колонки, схема), строить lineage (откуда данные приходят и куда уходят), обновлять
метаданные сущности. Список инструментов и точные сигнатуры — команда `/mcp`.

**Предпочитай MCP браузеру** для расследования источников данных — быстрее и
возвращает структурированные данные.

# Шаги выполнения

## Шаг 1: найти дашборд

```python
# Логин автоматический (коннектор superset). Найди целевой дашборд:
mcp__superset__list_dashboards(search="<ключевое слово>")
```

Как искать сломанные чарты через обзорный дашборд Superset и что делать, если
человек сразу дал конкретный дашборд — `references/data-source-tracing.md`.

## Шаг 2: сверить с реестром

Как только знаешь id/URL конкретного дашборда (из шага 1 или от человека
напрямую) — сверься с `context/dashboards.md`, **до** `get_dashboard`,
`get_chart_data` или скриншотов. Дашборд помечен «🚫 запрещено — правило 1» —
останавливаешься: дальше не идёшь ни по одному чарту этого дашборда, говоришь
человеку, что дашборд зарплатный и почему (правило 1, `CLAUDE.md`). Проверяешь
несколько дашбордов подряд (по команде) — прогоняешь эту сверку для каждого
из них перед тем, как читать его чарты.

## Шаг 3: список чартов дашборда

```python
mcp__superset__get_dashboard(id_or_slug="<id_or_slug>")     # название, владельцы, чарты
# точный список:
mcp__superset__list_dashboard_charts(dashboard_id=<id>)
```

## Шаг 4: найти сломанные чарты

```python
# Запускаем запрос каждого чарта — падающий чарт вернёт ошибку в ответе:
mcp__superset__get_chart_data(chart_id=<id>)
# Опционально визуально (случаи «пусто без ошибки»):
mcp__superset__get_dashboard_screenshot(dashboard_id=<id>)
mcp__superset__get_chart_screenshot(chart_id=<id>)
```

## Шаг 5: прочитать текст ошибки

```python
# mcp__superset__get_chart_data уже возвращает настоящую ошибку запроса (SQL/датасорс).
# Конфиг/датасорс за чартом:
mcp__superset__get_chart_params_summary(chart_id=<id>)
```

Что означает конкретный паттерн ошибки, в чём обычно причина и с чего начать
проверку — каталог типовых ошибок и порогов error rate/load time в
`references/error-catalog.md`.

## Шаг 6: проследить источник данных

```python
mcp__superset__get_dataset(dataset_id=<id>)
# Проверь таблицу в ClickHouse/Trino
```

Подробная методика трассировки от чарта → датасет → таблица → витрина и её
владелец — `references/data-source-tracing.md`.

## Шаг 7: сформировать отчёт об ошибках

Заполни отчёт по шаблону «Отчёт об ошибках дашборда» из `references/templates.md`.

## Шаг 8: спросить подтверждение

```markdown
Нашёл следующие сломанные чарты. Какие фиксы применить?

1. [ ] Обновить датасет 'X' на новое имя таблицы
2. [ ] Починить формулу метрики в датасете 'Y'
3. [ ] Увеличить таймаут для медленного запроса в настройках чарта
...

Ответь номерами фиксов (например, «1, 2») или «все»
```

## Шаг 9: выполнить подтверждённые фиксы

```python
# Правки датасета/чарта — через mcp__superset__update_dataset / update_chart
```

Какую стратегию применить в зависимости от типа проблемы (датасет, чарт,
источник) — `references/fix-strategies.md`.

### Проверка фикса
```python
# Вернись к дашборду
mcp__superset__get_chart_data(chart_id=<id>)  # ошибка ушла?
mcp__superset__get_dashboard_screenshot(dashboard_id=<id>)
```

**Обязательно прогони скилл `data-sanity`** для фактических цифр починенного
чарта — они должны сойтись с соседним периодом, прежде чем показать результат
человеку.

После этого — обязательный итоговый отчёт человеку по шаблону «Итоговый
отчёт» из `references/templates.md`, с таблицей было → стало по каждому фиксу.
