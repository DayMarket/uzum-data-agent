# Superset Dashboard Error Fixer

## Назначение

Автоматический дебаггер, который:
1. Находит чарты с ошибками на дашбордах Superset
2. Разбирает причину ошибки по логам и тексту ошибки
3. Прослеживает источники данных (датасеты, таблицы, DAG)
4. Предлагает и выполняет фиксы (только с подтверждением человека)

## Когда использовать

Используй этот скилл, когда просят:
- Починить сломанные чарты на дашборде
- Разобраться, почему чарт не грузится
- Проверить дашборды команды на ошибки
- Расследовать падения чартов и предложить фиксы

## Общий процесс

```
1. ЧЕЛОВЕК даёт URL дашборда или просит проверить дашборды команды
2. АГЕНТ находит чарты с ошибками
3. АГЕНТ читает тексты ошибок и логи
4. АГЕНТ прослеживает источники данных
5. АГЕНТ предлагает фиксы с объяснением
6. ЧЕЛОВЕК подтверждает конкретные фиксы
7. АГЕНТ выполняет только подтверждённые фиксы
```

## КРИТИЧНО: нужно подтверждение человека

**НИКОГДА не применяй фиксы без явного подтверждения!**

После того как нашёл проблемы:
1. Покажи полный список сломанных чартов
2. Объясни причину для каждой ошибки
3. Опиши, как каждую можно починить
4. Спроси, какие фиксы применить
5. Выполняй только то, что подтвердил человек

## Источники данных: OpenMetadata

**Для проверки источников данных и lineage используй коннектор `openmetadata` напрямую.**

Он умеет: искать датасеты/таблицы по имени, отдавать полную информацию о сущности
(колонки, схема), строить lineage (откуда данные приходят и куда уходят), обновлять
метаданные сущности. Список инструментов и точные сигнатуры — команда `/mcp`.

**Предпочитай MCP браузеру** для расследования источников данных — быстрее и
возвращает структурированные данные.

# Обнаружение ошибок

## Источник 1: обзорный дашборд Superset

**URL:** `https://bi.uzum.uz/superset/dashboard/superset_overview/`

### Какие фильтры применить
- **Фильтр по команде:** своя команда (например `ops` или `search`)
- **Период:** последние 7 дней (рекомендуется)

### Ключевые метрики
- Чарты с ошибками (error rate > 7%)
- Упавшие запросы
- Медленные чарты (загрузка > 10 сек)

### Как посмотреть
```python
# Логин автоматический (коннектор superset). Ищем дашборд по названию:
mcp__superset__list_dashboards(search="ops")
# Открываем, чтобы получить список чартов:
mcp__superset__get_dashboard(id_or_slug="<id_or_slug>")
```

## Источник 2: прямая проверка конкретного дашборда

Когда человек дал конкретный дашборд (id или slug — из URL):

```python
# Список чартов дашборда
mcp__superset__get_dashboard(id_or_slug="<id_or_slug>")
# Опционально: рендер всего дашборда, чтобы посмотреть глазами
mcp__superset__get_dashboard_screenshot(dashboard_id=<id>)
```

### Поиск чартов с ошибкой
Прогони запрос каждого чарта и посмотри результат:
- `mcp__superset__get_chart_data(chart_id=...)` → падающий запрос вернёт **ошибку** (SQL/датасорс) прямо в ответе.
- Пусто там, где ожидались данные → проверь `mcp__superset__get_chart_params_summary` + `mcp__superset__get_dataset`.
- «Пусто, но без ошибки» (проблема визуализации/фронта) → `mcp__superset__get_chart_screenshot(chart_id=...)`.

### Чтение деталей ошибки
`mcp__superset__get_chart_data` уже возвращает настоящую ошибку запроса. Для конфига
чарта и датасорса за ним: `mcp__superset__get_chart_params_summary(chart_id=...)` и
`mcp__superset__get_dataset(dataset_id=...)`.

# Разбор ошибки

## Частые типы ошибок

### 1. Таблица не найдена
**Паттерн ошибки:** `Table 'schema.table_name' doesn't exist`
**Причина:** таблицу переименовали, удалили или она никогда не создавалась
**Проверка:** запроси `information_schema` через `clickhouse` или `trino`

### 2. Колонка не найдена
**Паттерн ошибки:** `Column 'column_name' not found`
**Причина:** колонку переименовали или удалили в исходной таблице
**Проверка:**
```sql
DESCRIBE TABLE <schema.table>
```

### 3. Доступ запрещён
**Паттерн ошибки:** `Access denied` или `Permission denied`
**Причина:** поменялись права на датасет
**Фикс:** обновить права датасета в Superset

### 4. Таймаут запроса
**Паттерн ошибки:** `Query exceeded time limit`
**Причина:** неэффективный запрос, отсутствующие партиции, тяжёлые JOIN
**Проверка:** запрос чарта — нет ли пропущенного фильтра по партиционной колонке, нет ли дорогих JOIN

### 5. Несовпадение типов
**Паттерн ошибки:** `Type mismatch` или `Cannot cast`
**Причина:** поменялся тип колонки в источнике
**Фикс:** обновить расчётную колонку или формулу метрики

### 6. Витрина не долилась
**Паттерн ошибки:** данные не обновляются, старые даты
**Причина:** упал пайплайн, собирающий витрину
**Проверка:** сверь `max(date_column)` в таблице с ожидаемой датой обновления

# Прослеживание источника данных

## Шаг 1: найти датасет
Из ошибки чарта возьми имя датасета:
```python
mcp__superset__get_chart_params_summary(chart_id=<id>)
```

## Шаг 2: проверить датасет в Superset
```python
mcp__superset__get_dataset(dataset_id=<id>)
```
Посмотри исходную таблицу и SQL датасета.

## Шаг 3: проверить таблицу в ClickHouse/Trino
```sql
-- таблица существует?
SELECT * FROM system.tables WHERE name = '<table_name>'

-- свежие данные?
SELECT max(date_column) FROM <schema.table>
```

## Шаг 4: найти витрину и её источник
Если таблица — golden-витрина, свериться с `context/marts.md`: кто владелец, какое
доверие, есть ли оговорки. Дальше источник и пайплайн, собирающий витрину, уточняются
у владельца — жёстко зашитого пути к репозиторию с пайплайнами в этом воркспейсе нет.

# Стратегии фикса

## Фиксы на уровне датасета

### Обновить ссылку на колонку
```python
# Открой датасет в Superset
# Отредактируй расчётную колонку
# Обнови ссылку на колонку
```

### Починить формулу метрики
```python
# Датасет → Метрики
# Отредактируй метрику
# Обнови SQL-выражение
```

### Обновить ссылку на таблицу
Если таблицу переименовали:
```python
mcp__superset__update_dataset(dataset_id=<id>, ...)  # новое имя таблицы / SQL
```

## Фиксы на уровне чарта

### Обновить временную колонку
```python
mcp__superset__update_chart(chart_id=<id>, ...)  # смени time column на существующую
```

### Починить ссылку в фильтре
```python
mcp__superset__update_chart(chart_id=<id>, ...)  # обнови фильтр на валидную колонку
```

## Фиксы на уровне источника

### Витрина не долилась
1. Сообщи человеку: какая витрина, с какого числа не обновлялась
2. Это не чинится в Superset — нужен владелец витрины/пайплайна

### Структура таблицы поменялась
Если тип колонки изменился:
1. Проверь историю изменений витрины (если есть)
2. Предложи миграцию датасета или обратно совместимое изменение

# Пороги error rate

Из требований сертификации:
- **Норма:** error rate < 7% (за 7 дней)
- **Предупреждение:** error rate 7–15%
- **Критично:** error rate > 15%

Требования по времени загрузки чарта:
- **Хорошо:** ≤ 10 сек
- **Медленно:** 10–30 сек (нужна оптимизация)
- **Критично:** > 30 сек (обязательно чинить)

# Итоговый отчёт (ОБЯЗАТЕЛЕН)

**После выполнения всех подтверждённых фиксов ВСЕГДА дай сводку в этом формате:**

```markdown
# ✅ Починка ошибок завершена

## Дашборд: [Название]
URL: [url]
Команда: [команда]

## Сводка
- Найдено чартов с ошибками: X
- Починено: Y
- Пропущено (не подтверждено): Z

## Применённые фиксы (было → стало)

### Чарт 1: [Название]
| Параметр | Было | Стало |
|---|---|---|
| Статус | ❌ Ошибка | ✅ Работает |
| Ошибка | `Table 'schema.old_table' doesn't exist` | (устранена) |
| Таблица датасета | `schema.old_table` | `schema.new_table` |

### Чарт 2: [Название]
| Параметр | Было | Стало |
|---|---|---|
| Статус | ❌ Таймаут (45с) | ✅ Быстро (3с) |
| Запрос | Нет фильтра по партиции | Добавлен `WHERE date_uz >= today() - 7` |

## Что проверил (data-sanity)
[что сошлось: период, порядок величин, дубли, часовой пояс, источник]

## Не починено (человек отказался)
- [Чарт/проблема]: [причина отказа]

## Осталось сломанным (нужны ручные действия)
- [Чарт]: [почему нельзя починить автоматически]

## Проверка
- [ ] Обновил дашборд после фиксов
- [ ] Все починенные чарты грузятся
- [ ] Прогнал `data-sanity` на итоговых цифрах

## Дальше
1. [Ручные действия, если остались]
2. Проверить error rate на обзорном дашборде через 24ч
```

**КРИТИЧНО: для каждого применённого фикса всегда указывай таблицу было → стало.
Это обязательно для прозрачности и аудита.**
