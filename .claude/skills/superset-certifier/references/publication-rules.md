# Правила публикации (минимальные требования)

Перед публикацией (Draft → Published) у дашборда ДОЛЖНО быть:

## 1. Соглашение об именовании
- Начинается с префикса бизнес-линии: `Market`, `Ecom`, `Fintech` и т.п.
- Для дашбордов конкретной команды — свой понятный префикс/подпись
- Отражает содержание и назначение
- Хорошие примеры: `Market Ops Main KPI`, `Market: Marketing Overview`

## 2. Роли
- Добавлены роли по умолчанию для команды-владельца
- Если дашборд кросс-командный — создана отдельная гранулярная роль

## 3. Цветовые палитры
Должна использоваться одна из официальных палитр Uzum:
- **Uzum Berry** (рекомендуется, до 18 категорий)
- **Uzum Indigo** (до 12 категорий)
- **Uzum Spectrum** (до 21 категории)
- **Uzum Serenity** (градиент, для смешанных чартов)

## 4. Обязательные теги
У всех дашбордов ДОЛЖНЫ быть теги:
- `cat:` (категория)
- `team:` (команда-владелец)
- `crit:` (критичность: Tier1/Tier2/Tier3/Tier4)

## 5. Лендинг-страница (для важных дашбордов)
Требуется страница в Confluence с кратким описанием.
