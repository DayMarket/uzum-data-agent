# uzum-data-agent

Рабочее место операционного аналитика: скиллы, коннекторы к нашим системам и
общий контекст по витринам. Работает в двух движках — **Claude Code** и
**Codex** — установка одна и та же, дальше выбираешь движок сам (или ставишь
оба). Правила проекта — один файл, `CLAUDE.md`; `AGENTS.md`, который читает
Codex, — симлинк на него же, содержание всегда одинаковое.

## Установка

Сам движок (один или оба — ставить нужно хотя бы один):

- **Claude Code** — https://claude.com/code
- **Codex** — `npm install -g @openai/codex`

Что ещё должно стоять до установки (любым из двух путей ниже): `uv`
(`brew install uv`, им же поднимается `mcp-grafana` через `uvx`) и Node.js 18+
(`brew install node`, нужен только GrowthBook). Мастер проверит и скажет,
чего не хватает — в том числе движков: без хотя бы одного `./setup.sh`
дальше не пойдёт.

ClickHouse — это два независимых кластера с разными учётками (коннекторы
`clickhouse-wms` и `clickhouse-dwh`), не один источник с двумя адресами:
складской для операционной аналитики, общий DWH — для продаж/финансов/
маркетинга. Любой из двух можно пропустить при установке, подробности —
`connectors/ACCESS.md`.

Репозиторий приватный. Клонируем по HTTPS: у большинства ключи SSH на GitHub
не настроены, и `git@github.com:` упадёт с «make sure you have the correct
access rights» ещё до установки. Если GitHub попросит логин — заведи
Personal Access Token или поставь `gh` (`brew install gh`, затем `gh auth login`).

### Быстрый путь — заполнить файл

    git clone https://github.com/DayMarket/uzum-data-agent.git
    cd uzum-data-agent
    cp .env.example .env
    # впиши значения в .env, сверяясь с подсказками внутри файла
    # и с connectors/ACCESS.md
    ./setup.sh

`setup.sh` сам находит `.env` в корне репозитория (или по пути в переменной
`UZUM_ENV_FILE`, если файл лежит не здесь). Заполненные значения не
переспрашиваются, но живая проверка каждого доступа всё равно выполняется и
печатается — «вижу 47 баз», «вижу тебя как Denis Platon» и так далее: смысл
мастера не в том, чтобы принять значения на веру, а в том, чтобы показать,
что каждый доступ реально работает. Что не заполнено в `.env` — спросится
как обычно.

Заполнил файл целиком и вопросов не будет? `./setup.sh --non-interactive` не
спросит ничего: чего не хватает — покажет списком и завершится с ошибкой,
не трогая уже настроенное.

После успешной установки мастер напомнит, что `.env` хранит пароли в
открытом виде (секреты уже записаны в канонический файл,
`~/.config/uzum-ai/secrets.env`), и предложит удалить `.env` — по явному
согласию, не молча.

### Обычный путь — ответить на вопросы

    git clone https://github.com/DayMarket/uzum-data-agent.git
    cd uzum-data-agent
    ./setup.sh

Мастер спросит доступы по одному и проверит каждый живым запросом. Занимает
10–15 минут.

`./setup.sh` пишет конфиги для **обоих** движков за один проход — `.mcp.json`
для Claude Code и `.codex/config.toml` для Codex — независимо от того, какой
из них сейчас установлен на машине. Поставишь второй движок позже — конфиг
для него уже готов, `setup.sh` перезапускать не нужно.

## Первый запуск

Оба движка при первом запуске в этой папке спрашивают, доверяешь ли ты её
содержимому. **Отвечай «да» в обоих** — иначе коннекторы и хуки останутся в
подвешенном состоянии, и будет казаться, что ничего не работает, хотя на
самом деле просто не пройден диалог.

- **Claude Code** — один экран, стандартный диалог доверия папке.
- **Codex** — два экрана подряд. Первый — то же доверие папке. Второй,
  отдельный — «Hooks need review»: выбирай **«Trust all and continue»**. Если
  выбрать «Continue without trusting», сессия будет выглядеть обычной —
  инструменты вызываются, ответы приходят, — но хуки молча не запустятся, и
  строка этой сессии не попадёт в телеметрию. Ни ошибки, ни предупреждения
  при этом нигде не появится, это осознанное поведение Codex, не наш баг.
  В headless-режиме (`codex exec`, автоматизация) диалога вообще не будет —
  без прохождения его хотя бы раз в интерактивном `codex` хуки для этой
  папки не заработают никогда.

Диалог разовый: следующие сессии (включая `uzum`) его не переспрашивают,
пока хуки не изменятся.

## Работа

Синтаксис вызова скилла зависит от движка — это не опечатка и не баг, если
скилл «не сработал», а ты в чате набрал не тот символ:

| | Claude Code | Codex |
|---|---|---|
| запуск | `uzum` или `uzum --claude` | `uzum` или `uzum --codex` |
| вызвать скилл | **`/task OE-3491`** (слэш) | **`$task OE-3491`** (доллар) |
| починить доступ | `/fix-access` | `$fix-access` |

`uzum` без флага сам решает, какой движок запускать: если стоит только один —
берёт его; если оба — либо помнит твой прошлый явный выбор, либо спросит.
`uzum --claude` / `uzum --codex` — явный выбор на этот раз, ничего не меняет
в запоминании.

Рабочие файлы по задачам складываются в `work/<ключ>/` — эта папка личная и в git
не попадает.

Скиллы, контекст и реестры едут через репозиторий, поэтому в начале каждой
сессии — в обоих движках — выполняется `git pull` и сессия сообщает, что
приехало. Отдельно делать ничего не нужно. Если обновиться не удалось (обычно
это конфликт с твоими правками), сессия скажет об этом прямо и продолжит
работать на том, что есть.

## Что мы собираем

Хуки пишут в ClickHouse полный лог сессий: твои запросы, ответы агента, вызовы
инструментов, время и токены, для обоих движков — в общих таблицах, с
отдельной колонкой, каким движком получена строка (`claude` или `codex`). Мы
смотрим это, чтобы чинить скиллы и понимать, что работает, а что нет. Для
оценки людей эти данные не используются.

Секреты (пароли, токены) маскируются до записи.

## Ограничения Codex

Четыре вещи, которые честно устроены иначе, чем хотелось бы, и мы не можем
это поменять сами (это чужие пакеты и встроенное поведение Codex):

1. **Шесть коннекторов из девяти спрашивают подтверждение на каждый вызов**,
   включая безобидное перечисление таблиц. Codex решает, спрашивать ли
   подтверждение, по признаку `readOnlyHint`, который выставляет сам код
   инструмента — мы проставили его там, где коннектор пишем сами (Trino,
   Superset). У остальных шести — оба кластера ClickHouse (`clickhouse-wms`,
   `clickhouse-dwh`, наш основной источник данных), Jira с Confluence (один
   коннектор `atlassian`), Grafana, OpenMetadata, GrowthBook — это сторонние
   пакеты, признака у них нет, и заменить его нечем. Это не дыра в
   безопасности (наоборот, более осторожное поведение по умолчанию), но
   ожидай больше вопросов, чем в Claude Code, особенно от ClickHouse.
   Подробности — `connectors/ACCESS.md`.
2. **Список запрещённых для чтения мест — это список, а не граница.**
   `.env` и общеизвестные хранилища секретов (`~/.ssh`, `~/.aws` и другие,
   полный перечень — `lib/known_secret_paths.py`) агент прочитать не может
   ни в одном из движков. Файл с паролем в любом другом, нестандартном
   месте на диске — может: ни Codex, ни Claude Code не смотрят на
   содержимое файла, только на путь. Не клади секреты мимо
   `~/.config/uzum-ai/secrets.env` и не рассчитывай, что список сам
   расширится под твой случай.
3. **Один раз нужно пройти диалог доверия хукам** — см. «Первый запуск»
   выше. Пропустишь его — сессия будет выглядеть рабочей, а телеметрия
   молча писаться не будет, без единого предупреждения.
4. **Запускай строго через `uzum`, не через голый `codex`.** Профиль
   разрешений (запрет читать секреты, запись только в `work/`) доставляется
   не в основной `config.toml` Codex, а отдельным именованным профилем —
   он подключается только флагом `-p uzum`, который добавляет `uzum`. Голый
   `codex` в этой же папке этот флаг не передаёт, значит запускается без
   профиля вообще — ни запрет на чтение `.env`/секретов, ни ограничение
   записи не действуют, а сессия при этом выглядит совершенно рабочей,
   никакого предупреждения не будет. Это подтверждено тестом
   (`tests/test_codex_permissions.py::test_live_undeployed_config_gives_no_technical_protection`
   — реальный `cat .env` без нашего профиля отдаёт секрет в вывод дословно).
   Для Claude Code голый `claude` работает сам по себе не так рискованно
   (разрешения лежат в `.claude/settings.json` и подхватываются им
   автоматически), но `uzum` в любом случае ещё и подгружает секреты в
   окружение — без него коннекторы просто не увидят кредов.

## Тесты (для тех, кто правит сам репозиторий)

    uv run --python 3.12 --with pytest --with google-auth --with requests \
        python -m pytest tests/ -q

Именно так, а не голым `python3 -m pytest`: коннекторы объявляют зависимости
для `uv run`, а не для системного питона. На чистом ноутбуке системным
интерпретатором набор просто нечем запустить — а на ноутбуке, где нужные пакеты
случайно оказались в системном Python 3.9, он проходит с предупреждениями об
интерпретаторе, до которого нам нет дела.

## Куда бежать

Не работает — `/fix-access` (Claude Code) или `$fix-access` (Codex) прямо в
сессии. Не помогло — Настя Бир.
