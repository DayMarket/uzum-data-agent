# uzum-data-agent

Рабочее место операционного аналитика в Claude Code: скиллы, коннекторы к нашим
системам и общий контекст по витринам.

## Установка

    git clone git@github.com:DayMarket/uzum-data-agent.git
    cd uzum-data-agent
    ./setup.sh

Мастер спросит доступы и проверит каждый живым запросом. Занимает 10–15 минут.

Что должно стоять до него: `uv` (`brew install uv`), `mcp-grafana`
(`brew install mcp-grafana`) и Node.js 18+ (`brew install node`, нужен только
GrowthBook). Мастер проверит и скажет, чего не хватает.

## Работа

    uzum                  запустить сессию
    /task OE-3491         взять задачу из Jira
    /fix-access           если что-то отвалилось

Рабочие файлы по задачам складываются в `work/<ключ>/` — эта папка личная и в git
не попадает.

## Что мы собираем

Хуки пишут в ClickHouse полный лог сессий: твои запросы, ответы агента, вызовы
инструментов, время и токены. Мы смотрим это, чтобы чинить скиллы и понимать,
что работает, а что нет. Для оценки людей эти данные не используются.

Секреты (пароли, токены) маскируются до записи.

## Тесты (для тех, кто правит сам репозиторий)

    uv run --python 3.12 --with pytest --with google-auth --with requests \
        python -m pytest tests/ -q

Именно так, а не голым `python3 -m pytest`: коннекторы объявляют зависимости
для `uv run`, а не для системного питона. На чистом ноутбуке системным
интерпретатором набор просто нечем запустить — а на ноутбуке, где нужные пакеты
случайно оказались в системном Python 3.9, он проходит с предупреждениями об
интерпретаторе, до которого нам нет дела.
