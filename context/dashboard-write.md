# Правка дашборда: как сохранять, чтобы не потерять

> Читается **до первой записи** в любой дашборд — Superset или Grafana.
> Скиллы `dashboard-fix` и `superset-fixer` ссылаются сюда с шага правки.
> Общий запрет на запись — правило 6 в `context/rules.md`.

## Что случилось 18.08.2026

Задача была «поправить SQL, чтобы дашборд не падал на пустом фильтре».
Итог — **10 дашбордов Grafana стали недоступны**. Восстановили из бэкапа,
сделанного по другому поводу; ссылки поменялись, у людей они битые.

```
Дашборд лежит в рабочей папке
        ↓
Полное сохранение JSON без folderUid
        ↓
Теряется привязка к папке
        ↓
Больше не наследуются права этой папки
        ↓
DTO endpoint отвечает 403
        ↓
Дашборд не открывается и не виден в поиске — фактически удалён
```

## Корень: объект состоит из двух частей, и вторая не в JSON

| Часть | Где живёт | Если не передать |
|---|---|---|
| Панели, запросы, переменные, название, UID | в JSON дашборда | — |
| Папка и наследуемые от неё права | **вне JSON**, параметр `folderUid` | дашборд уезжает из папки, права теряются, 403 |

Прочитав полный JSON, папку **не увидишь — её там нет**. Отправив тот же JSON
обратно, ты не «оставишь папку как была», а снесёшь её.

**Полное сохранение — это замена, а не правка.** Поле, которого нет в теле
запроса, принимает значение по умолчанию. Отсутствие поля — это тоже изменение.
Правило общее: то же верно для датасетов и чартов Superset, задач Jira, страниц
Confluence. Перед записью выясни, какие поля живут вне тела объекта.

В Grafana 12 дашборды обслуживает Kubernetes-style API `dashboard.grafana.app`.
На сохранение без корректной folder/ACL-привязки он всё равно отвечает
`status: success` — **успешный ответ ничего не подтверждает.**

## Порядок

1. **Бэкап до всего.** В `work/<дата>_<задача>/backup/`: полный JSON, `uid`,
   **`folderUid`**, `version`, ссылка. Нет файла — запись не начинается.
2. **`folderUid` добыть отдельным чтением** — из JSON он не берётся.
3. **Изменить ОДИН дашборд**, передав `folderUid` явно вместе с телом.
4. **Проверить чтением, а не ответом API:**
   - дашборд открывается по своему URL;
   - он на месте в поиске;
   - `folderUid` в ответе совпадает с сохранённым в п.1;
   - панель, ради которой всё затевалось, действительно чинится — в том числе
     на пустом фильтре, если правился именно этот кейс.
5. **Показать человеку и дождаться «ок».**
6. Только теперь — остальные, **по одному**, с той же проверкой после каждого.

Пачка превращает одну ошибку в десять. Потеря даже одного дашборда — инцидент,
так что «сначала один» это минимум, а не индульгенция.

## Стоп-условия — прекратить немедленно

- 403 / 404 / «не найден» на дашборде, который только что сохранил;
- `folderUid` после сохранения пустой или не тот;
- дашборд пропал из поиска;
- ответ API отличается от того, что был на первом, проверенном дашборде.

Реакция:

1. **СТОП.** Остальные не трогать. Никаких «доделаю, потом разберусь».
2. Сказать человеку прямым текстом: «я, возможно, сломал X, остановился,
   не откачено».
3. Разобраться, что означает код ответа, **прежде чем** списывать его на
   ограничение MCP, VPN или прав токена.

Ошибка доступа сразу после собственной записи — улика против себя, а не
особенность инструмента. Списать её на «ограничение MCP» — худший исход
инцидента: человек узнаёт о потере на день позже и уже без простого отката.

## Если уже сломано

Дашборды при этом **не удаляются**: UID, содержимое и версии остаются в
Grafana, недоступной становится привязка. Поэтому первым делом — вернуть
`folderUid` тому же UID: тогда уцелеют и ссылки. Восстановление из бэкапа даёт
новые UID и ломает все существующие ссылки у пользователей — это запасной
вариант, а не первый. Прав может не хватить: идти к админам Grafana, а не
пытаться пересоздать.
