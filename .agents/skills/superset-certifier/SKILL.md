# Superset Dashboard Certifier

## Назначение

Автоматическая проверка дашборда на соответствие:
1. **Правилам публикации** (минимальные требования перед публикацией)
2. **Требованиям сертификации** (3 уровня в зависимости от критичности дашборда)

## Когда использовать

Используй этот скилл, когда просят:
- Проверить, соответствует ли дашборд правилам публикации
- Провалидировать дашборд для сертификации
- Проверить соответствие дашборда корпоративным стандартам
- Подготовить дашборд к подаче на сертификацию

## Общий процесс

```
1. ЧЕЛОВЕК даёт URL дашборда
2. АГЕНТ смотрит свойства и чарты дашборда через коннектор superset
3. АГЕНТ проверяет все требования
4. АГЕНТ формирует отчёт о соответствии со списком проблем
5. АГЕНТ предлагает фиксы
6. ЧЕЛОВЕК подтверждает конкретные фиксы
7. АГЕНТ выполняет только подтверждённые фиксы
```

## КРИТИЧНО: нужно подтверждение человека

**НИКОГДА не применяй фиксы без явного подтверждения!**

После отчёта о соответствии:
1. Покажи полный список найденных проблем
2. Для каждой — опиши, как её починить
3. Спроси, какие фиксы применить
4. Выполняй только то, что подтвердил человек

## Изменения в OpenMetadata

**Для любых изменений в OpenMetadata (OMD) используй коннектор `openmetadata` напрямую.**

Он умеет: искать дашборды/таблицы/метрики, получать полную информацию о сущности,
обновлять сущность (описание, владельцев, теги и т.д.), проверять lineage.
Список инструментов и точные сигнатуры: в Claude Code — команда `/mcp`; в
Codex такой команды нет — спроси у самого коннектора или посмотри
`connectors/ACCESS.md`.

**Предпочитай MCP браузеру** для изменений в OMD — быстрее и надёжнее.

Полный список требований публикации — `references/publication-rules.md`; уровни
сертификации и критичности (Tier 1–4) — `references/certification-levels.md`.

# Шаги выполнения

## Шаг 1: получить URL дашборда
```
Человек даёт: https://bi.uzum.uz/superset/dashboard/XXXX/
```

## Шаг 2: сверить с реестром
Возьми id или slug дашборда из URL и сверься с `context/dashboards.md` —
**до** того как открывать дашборд или звать любой инструмент `superset`.
Дашборд помечен «🚫 запрещено — правило 1» — останавливаешься сразу: не
открываешь, не читаешь свойства, не снимаешь скриншот, не сертифицируешь.
Скажи человеку, что дашборд зарплатный и почему (правило 1, `CLAUDE.md`). Не
в реестре или без пометки — переходи к шагу 3 обычным порядком.

## Шаг 3: открыть дашборд
Логин автоматический (коннектор `superset` сам делает Keycloak SSO). Возьми id или
slug дашборда из URL, который дал человек.

## Шаг 4: прочитать свойства дашборда
```python
mcp__superset__get_dashboard(id_or_slug="<id_or_slug>")   # название, владельцы, описание, published, роли, чарты
```

## Шаг 5: визуальная проверка (опционально)
```python
mcp__superset__get_dashboard_screenshot(dashboard_id=<id>)
```

## Шаг 6: проверить свойства
Из `mcp__superset__get_dashboard` выше проверь (полный список требований —
`references/publication-rules.md`):
   - Название (соглашение об именовании)
   - Назначенные роли
   - Цветовую схему
   - Теги (cat:, team:, crit:)

## Шаг 7: проверить чарты
Для каждого чарта:
1. Убедись, что нет ошибки
2. Проверь, что название информативное
3. Проверь использование палитры
4. Проверь, определены ли метрики на уровне датасета

## Шаг 8: проверить внешние источники

### OpenMetadata (OMD)
Через коннектор `openmetadata` найди дашборд по названию и проверь:
- Domain, Owner, Tier, Description
- Частоту обновления данных
- Связанные метрики

### Обзорный дашборд Superset
Открой: `https://bi.uzum.uz/superset/dashboard/superset_overview/`
Примени фильтры:
- Команда: команда-владелец проверяемого дашборда
- Последние 7 дней

Проверь по дашборду/чартам:
- error rate < 7%
- загрузка ≤ 10 сек

Полные критерии по уровням 1–3 — `references/certification-levels.md`.

## Шаг 9: сформировать отчёт о соответствии

Заполни отчёт по шаблону «Отчёт о сертификации дашборда» из `references/templates.md`.

## Шаг 10: спросить подтверждение

Покажи список фиксов:
```markdown
Нашёл следующие проблемы. Какие фиксы применить?

1. [ ] Добавить недостающий тег `crit:Tier2`
2. [ ] Добавить недостающий тег `team:<команда>`
3. [ ] Обновить название дашборда под соглашение об именовании
4. [ ] Создать страницу в Confluence с описанием
5. [ ] Добавить роли по умолчанию
...

Ответь номерами фиксов (например, «1, 2, 3») или «все»
```

## Шаг 11: выполнить подтверждённые фиксы

### Фикс тегов
```python
# Теги / сертификация живут в json_metadata дашборда. Прочитать, поправить, записать:
mcp__superset__get_dashboard(id_or_slug="<id>")
mcp__superset__update_dashboard(dashboard_id=<id>, json_metadata="<обновлённый json с тегами/сертификацией>")
```

### Создание страницы в Confluence
Страницы с описанием дашборда создаются дочерними к разделу документации по
дашбордам в Confluence (адрес узнай у владельца пространства, если не знаешь).

**ПЕРЕД созданием страницы СПРОСИ у человека:**
```
Для создания страницы описания дашборда нужна информация:

1. Какая частота обновления данных? (например: ежедневно, раз в час, real-time)
2. Во сколько обновляются данные? (UTC+5, например: 08:00)

Пожалуйста, укажи эти данные.
```

Создай страницу через коннектор `atlassian` (Confluence): пространство, родительская
страница, название = название дашборда, содержимое — сгенерированное описание с
частотой обновления.

### Обновление OpenMetadata
**ВАЖНО:** в OMD добавляй ТОЛЬКО краткое описание (не полный текст страницы Confluence).

Описание должно быть кратким саммари, например:
> «Дашборд для анализа производительности склада N: OPH/OPS по сменам и зонам,
> сверка с нормой выработки.»

```python
# Через коннектор openmetadata: обновить описание и домен сущности дашборда
```

**Confluence-страница** содержит все детали (частота обновления, источники данных,
пайплайны, метрики).
**OpenMetadata** содержит только краткое описание + Domain.

После этого — обязательный итоговый отчёт человеку по шаблону «Итоговый
отчёт» из `references/templates.md`, с таблицей было → стало по каждому
изменению.
