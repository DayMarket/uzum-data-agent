# Установка на macOS

Пошагово, с проверкой после каждого шага. Занимает 20–30 минут, из которых
10–15 — сам мастер. Общая часть, одинаковая для macOS и Windows, — в
[README этой папки](README.md).

## Шаг 0. Что нужно иметь до начала

Два доступа выдаются не мгновенно — если их ещё нет, закажи сейчас, а
установку продолжай: мастер спокойно доносит их позже.

| Что | Где взять |
|---|---|
| Пароль к ClickHouse WMS | Заявка в JSM, «Доступ к DWH». Логин — корп-почта через дефис |
| Токен Jira | Профиль → Personal Access Tokens → Create token |
| Netbird | Ставится с правами администратора на ноутбуке, см. [ACCESS.md](../../connectors/ACCESS.md) |

Права администратора на ноутбуке нужны один раз — для Netbird.

## Шаг 1. Командная строка разработчика

Даёт `git` и системный `python3`:

    xcode-select --install

Откроется окно установки — согласись и дождись конца. Проверка:

    git --version && python3 --version

Обе команды должны напечатать версию. Если `xcode-select` говорит, что
инструменты уже установлены, — так и есть, иди дальше.

## Шаг 2. Homebrew

Если `brew --version` уже отвечает — пропускай. Иначе:

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

На Apple Silicon установщик в конце печатает две команды с `eval
"$(/opt/homebrew/bin/brew shellenv)"` — их нужно выполнить, иначе `brew` не
появится в PATH этой сессии терминала. Проверка:

    brew --version

## Шаг 3. `uv` и Node.js

`uv` обязателен: через него поднимается каждый из девяти коннекторов
(`uv run` для наших, `uvx` для сторонних). Node нужен для GrowthBook, и
им же ставится Codex.

    brew install uv node

Проверка — обе должны ответить версией:

    uv --version && npx --version

## Шаг 4. Netbird

Без туннеля прод-данных не будет: ClickHouse, Trino, Grafana и OpenMetadata
доступны только из корпоративной сети. Установка — по
[ACCESS.md](../../connectors/ACCESS.md), нужны права администратора.

Проверка:

    netbird status

Нужна строка про подключённое состояние и ненулевое число пиров. Ноль
пиров — это не «работает»: маршруты до прод-сетей раздают именно пиры, и
мастер на такое состояние отдельно ругается.

## Шаг 5. Движок

Хотя бы один. Оба ставить не обязательно — и лишний движок означает лишний
диалог доверия, который легко пропустить и потом гадать, почему не работает.

    # Codex
    npm install -g @openai/codex
    codex login

    # Claude Code — по инструкции с https://claude.com/code

`codex login` открывает браузер. Сделать это нужно **до** мастера: мастер
проверяет доверие хукам живым запуском `codex exec` и без
`~/.codex/auth.json` честно откажется — а читается это как «установка
сломалась».

## Шаг 6. Клонировать репозиторий

По HTTPS, не по SSH: ключи SSH на GitHub настроены не у всех, и
`git@github.com:` упадёт с «make sure you have the correct access rights»
ещё до установки.

    cd ~
    git clone https://github.com/DayMarket/uzum-data-agent.git
    cd uzum-data-agent

Репозиторий приватный. Если GitHub спросит логин и пароль — пароль не
подойдёт, нужен Personal Access Token, либо поставь `gh`:

    brew install gh && gh auth login

## Шаг 7. Заполнить доступы файлом — или ответить на вопросы

Два равноправных пути, выбирай любой.

**Файлом** — удобнее, если доступы уже под рукой:

    cp .env.example .env
    open -e .env        # или любой редактор

Заполни, сверяясь с подсказками внутри файла. Минимум, чтобы начать
работать, — три значения: `CH_WMS_USER`, `CH_WMS_PASSWORD`, `JIRA_TOKEN`
(хосты уже проставлены). Заполненное мастер не переспросит, но проверит
живым запросом всё равно.

**Вопросами** — ничего не заполняй, мастер спросит сам.

## Шаг 8. Мастер

    ./setup.sh

Что происходит и что читать в выводе:

- **«Проверяю окружение…»** — движки, `python3`, `curl`, `uv`, `npx`,
  Netbird. Красная строка здесь означает, что дальше идти бессмысленно, и
  мастер сам скажет, что поставить.
- **Коннекторы по одному.** На каждый — вопрос (или подстановка из `.env`)
  и живая проверка. `✓` значит, что сервер реально ответил.
- **Телеметрия.** Не спрашивается вовсе, но проверяется **пробной
  записью** — вставкой без единой строки. Нет прав `INSERT` в `sandbox` —
  мастер скажет словами и **не** будет считать установку сломанной:
  работает всё, кроме сбора статистики. Строки при этом не теряются, копятся
  в очереди и уедут, когда права появятся.
- **Итог.** Что включено, что нет и какой командой донести каждое
  недостающее. Самой последней строкой — чего не хватает из **обязательного**.
  Её стоит дочитать: «Готово» без неё и «Готово» с ней — разные вещи.

Заполнил `.env` целиком и вопросов не хочешь вовсе:

    ./setup.sh --non-interactive

Мастер ничего не спросит: чего не хватает — покажет списком и завершится с
ошибкой, не тронув уже настроенное.

В конце мастер предложит удалить `.env` — там пароли открытым текстом, а
секреты к этому моменту уже записаны в `~/.config/uzum-ai/secrets.env`.
Соглашайся.

## Шаг 9. Команда `uzum` в PATH

Если мастер сказал, что `uzum` не виден, — добавь в `~/.zshrc` и открой
новый терминал:

    export PATH="$HOME/.local/bin:$PATH"

Проверка:

    which uzum

## Шаг 10. Первый запуск

    uzum

Движок спросит, доверяешь ли ты этой папке. **Отвечай «да»** — иначе
коннекторы и хуки останутся в подвешенном состоянии, и будет казаться, что
ничего не работает.

У **Codex** экрана два: сначала доверие папке, потом отдельный «Hooks need
review» — там выбирай **«Trust all and continue»**. «Continue without
trusting» оставляет сессию, которая выглядит совершенно обычной, но хуки в
ней молча не запускаются. Ни ошибки, ни предупреждения при этом не будет —
это поведение Codex, а не наш баг.

Перепроверить, что доверие выдано:

    ./setup.sh --add codex-hooks

## Шаг 11. Первая задача

    $task MAD-1234      # Codex
    /task MAD-1234      # Claude Code

Сломалось — `$fix-access` или `/fix-access` прямо в сессии.

## Если что-то не так

| Симптом | Что это |
|---|---|
| `zsh: command not found: uzum` | Шаг 9 — PATH. Либо запускай как `~/.local/bin/uzum` |
| Мастер: «Netbird не подключён» | `netbird up`, состояние — `netbird status` |
| Мастер: «пиров: 0/2» | Туннель поднят, но маршруты до прод-сетей не раздаются. Подожди несколько секунд после `netbird up` и запусти мастер заново |
| ClickHouse отвечает 401 | Пароль не тот. Логин — корп-почта **через дефис**, не через точку |
| Коннектора нет в сессии | Скорее всего, так и задумано: без кредов он не включается. Мастер перечислил такие в конце — донеси доступ и `./setup.sh --add <коннектор>` |
| `✔ Connected` есть, а инструмент не работает | Этот признак означает «процесс удалось запустить», а не «инструмент работает». Настоящая проверка — вызвать инструмент на чтение; ровно это делает `fix-access` |
| Codex спрашивает подтверждение на каждый вызов | Так и есть: шесть коннекторов из девяти — сторонние пакеты без признака `readOnlyHint`. Это не поломка, см. «Ограничения Codex» в README |
