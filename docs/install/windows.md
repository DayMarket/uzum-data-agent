# Установка на Windows

Идёт внутри WSL2 — это Ubuntu, которая ставится как обычное приложение и так
же удаляется, не вторая система и не виртуалка, которую нужно настраивать.
Занимает 30–40 минут, из которых 10–15 — мастер, задающий вопросы про
доступы.

## Коротко

В **PowerShell от администратора**, один раз:

    wsl --install -d Ubuntu

Перезагрузка. При первом запуске Ubuntu попросит придумать логин и пароль —
это отдельная учётка Linux, не пароль Windows; `sudo` будет спрашивать
именно её.

Дальше **всё в терминале Ubuntu**:

    sudo apt update && sudo apt install -y git
    cd ~ && git clone https://github.com/DayMarket/uzum-data-agent.git
    cd uzum-data-agent && ./install-windows.sh

Установщик доводит систему до рабочего состояния и передаёт управление
мастеру, который спросит доступы. Один раз он может попросить перезапустить
WSL (`wsl --shutdown` в PowerShell) — это нужно, чтобы Ubuntu увидела
корпоративную сеть; после перезапуска продолжай командой `./setup.sh`.

Всё. Ниже — что понадобится по дороге, что установщик делает и что читать,
если что-то пошло не так.

## Что нужно иметь до начала

Два доступа выдаются не мгновенно — если их ещё нет, закажи сейчас, а
установку продолжай: мастер спокойно доносит их позже.

| Что | Где взять |
|---|---|
| Пароль к ClickHouse WMS | Заявка в JSM, «Доступ к DWH». Логин — корп-почта через дефис |
| Токен Jira | Профиль → Personal Access Tokens → Create token |
| Netbird | Ставится **на Windows**, с правами администратора, см. [ACCESS.md](../../connectors/ACCESS.md) |
| Права администратора | Нужны для `wsl --install` и для Netbird |
| Доступ к приватному репозиторию | Логины GitHub из Windows в WSL не переезжают: внутри Ubuntu нужен свой Personal Access Token либо `sudo apt install gh && gh auth login` |

Netbird ставится на Windows и остаётся там — внутрь WSL его ставить не нужно.

## Что делает `install-windows.sh`

- проверяет, что это действительно WSL, а не Git Bash, и что репозиторий не
  лежит на диске Windows;
- **настраивает сеть**: WSL2 по умолчанию живёт за собственным NAT и в
  туннель Netbird не попадает, из-за чего ClickHouse не отвечает, а выглядит
  это как неверный пароль. Установщик находит `%UserProfile%\.wslconfig` со
  стороны WSL и, если зеркального режима там нет, прописывает его сам.
  Настройка применяется только после перезапуска WSL — поэтому в этом случае
  он останавливается и говорит, чем продолжить;
- ставит недостающее: `curl`, `python3`, `uv`, Node.js;
- спрашивает движок (Codex, Claude Code или оба) и ставит его;
- логинит Codex — **до** мастера, а не после: мастер проверяет доверие хукам
  живым запуском `codex exec` и без `~/.codex/auth.json` честно откажется, а
  читается это как «установка сломалась»;
- передаёт управление `./setup.sh`.

Доступов установщик не спрашивает вовсе — это работа мастера, и она здесь не
продублирована. Аргументы уходят мастеру как есть, так что если `.env`
заполнен заранее, работает и `./install-windows.sh --non-interactive`.

Чужой `.wslconfig` установщик не переписывает: если файл уже есть, но
зеркального режима в нём нет, он покажет, что дописать, и не тронет чужие
настройки — там могут лежать лимиты памяти или своё ядро.

## Что читать в выводе мастера

- **«Проверяю окружение…»** — движки, `python3`, `curl`, `uv`, `npx`,
  Netbird. Про Netbird в WSL мастер скажет отдельно: его команды здесь нет и
  не должно быть, клиент стоит на Windows.
- **Коннекторы по одному** — вопрос (или подстановка из `.env`) и живая
  проверка. `✓` значит, что сервер реально ответил, а не что значение
  приняли.
- **Смоук-тест ClickHouse** — вот он и есть настоящая проверка сети.
  Изнутри WSL состояние туннеля снять нечем, поэтому ни установщик, ни
  мастер не станут утверждать, что с сетью всё в порядке: показывает только
  реальный запрос.
- **Итог** — что включено, что нет и какой командой донести недостающее.
  Самой последней строкой — чего не хватает из **обязательного**; её стоит
  дочитать, «Готово» с ней и без неё означают разное.

Минимум, чтобы начать работать, — три значения: `CH_WMS_USER`,
`CH_WMS_PASSWORD`, `JIRA_TOKEN`. Остальные семь коннекторов добавляются
потом: `./setup.sh --add <коннектор>`.

## Первый запуск

    uzum

Если команда не находится — добавь в `~/.bashrc` и открой новый терминал:

    export PATH="$HOME/.local/bin:$PATH"

У **Codex** будет два экрана подряд: доверие папке, а затем отдельный «Hooks
need review» — там выбирай **«Trust all and continue»**. «Continue without
trusting» оставляет сессию, которая выглядит совершенно обычной, но хуки в
ней молча не запускаются. Ни ошибки, ни предупреждения при этом не будет —
это поведение Codex, а не наш баг. Перепроверить, что доверие выдано:
`./setup.sh --add codex-hooks`.

Первая задача:

    $task MAD-1234      # Codex
    /task MAD-1234      # Claude Code

Сломалось — `$fix-access` прямо в сессии.

## Если что-то пошло не так

| Симптом | Что это |
|---|---|
| ClickHouse не отвечает, пароль точно верный | Сеть. Проверь, что после правки `.wslconfig` был `wsl --shutdown`, и что Netbird поднят на Windows |
| Мастер сразу говорит «это Git Bash, а не Linux» | Ты в Git Bash, а не в Ubuntu. Открой терминал WSL: «Пуск» → Ubuntu |
| Установщик: «репозиторий лежит на диске Windows» | Клон в `/mnt/c/…`. Переклонируй в `~` — см. ниже |
| Установщик: «не нашёл домашнюю папку Windows» | Не смог дотянуться до Windows-стороны. Создай `%UserProfile%\.wslconfig` блокнотом, содержимое он покажет |
| `./setup.sh: /usr/bin/env: bad interpreter` | Скрипт с CRLF. Так бывает, если клон делали Windows-гитом до появления `.gitattributes` — переклонируй изнутри WSL |
| `exec: node: not found` или `Missing optional dependency @openai/codex-linux-x64` при запуске `uzum` | Запускается Codex, установленный **в Windows**: WSL подмешивает Windows-PATH, и npm-шим `codex` оттуда виден отсюда. Нужен Codex внутри Ubuntu: `npm install -g @openai/codex`. Проверка — `which codex` должен показать `/usr/bin/...`, а не `/mnt/c/...` |
| Мастер: «Codex не авторизован» | `codex login`, затем `./setup.sh --add codex-hooks` |
| `bash: uzum: command not found` | PATH, см. «Первый запуск» |
| Коннектора нет в сессии | Скорее всего, так и задумано: без кредов он не включается. Донеси доступ и `./setup.sh --add <коннектор>` |
| Codex спрашивает подтверждение на каждый вызов | Так и есть, см. «Ограничения Codex» в README. Не поломка |

### Зеркальный режим сети — подробности

Нужна **Windows 11 22H2 или новее**; на Windows 10 зеркального режима нет,
приходи, разберёмся отдельно. Файл `%UserProfile%\.wslconfig` на стороне
Windows:

    [wsl2]
    networkingMode=mirrored
    dnsTunneling=true

После правки — `wsl --shutdown` в PowerShell и открыть Ubuntu заново.

### Почему клонировать в `~`, а не в `/mnt/c/…`

Домашняя папка WSL — её собственная файловая система. На диске Windows всё
работает в разы медленнее, а git показывает изменения, которых никто не
делал: на этом обрывается `git pull --ff-only` в хуке старта сессии, то есть
скиллы перестают обновляться. Установщик на `/mnt/` откажется работать и
попросит переклонировать.

Переводы строк настраивать не нужно: `.gitattributes` в репозитории
заставляет git отдавать LF на любой машине.

## Почему только WSL2

Git Bash выглядит подходящим, и в этом главная опасность: bash там
настоящий, `curl` есть, установка проходит заметную часть пути. Ломается она
позже и по частям.

1. **Профиль разрешений Codex не применяется.** `.codex/config.toml`
   описывает запреты POSIX-путями — `/**/*.env`, `~/.ssh`, запись только в
   `work/`. На Windows-путях это не срабатывает вовсе. Получается ровно
   случай из «Ограничений Codex», пункт 4: агент читает `.env` и ключи,
   сессия при этом выглядит совершенно рабочей, предупреждения нет.
2. **Симлинки превращаются в текстовые файлы.** Их в репозитории
   тринадцать: `AGENTS.md` указывает на `CLAUDE.md`, и все двенадцать
   скиллов в `.claude/skills/` — на `.agents/skills/`. Git для Windows без
   `core.symlinks=true` кладёт вместо них обычные файлы со строчкой пути
   внутри. Codex вместо правил проекта прочитает слово «CLAUDE.md», а ни
   один скилл не найдётся. Тоже молча.
3. **Мелочи, которые видно сразу:** `python3` в MSYS2 называется иначе,
   `~/.config/uzum-ai` уезжает в профиль MSYS.

Общее у всех трёх — установка не падает, а тихо получается неполной. Поэтому
`./setup.sh`, запущенный в Git Bash, останавливается первой же строкой и
отправляет сюда.

Нативная сборка Codex под Windows существует, и её песочница развивается, но
наш профиль разрешений на ней не проверялся ни разу. Сама OpenAI держит WSL2
рекомендованным способом запускать Codex на Windows: там работает тот же
сандбокс, что на Linux.
